# Noms des secrets d'Actions de la forge qui ne sont **pas** des valeurs légales (AD-12, AD-14).
# Un nom par ligne ; « # » commente, les lignes vides sont ignorées. Aucune valeur n'entre ici : ce
# fichier ne porte que des noms, et il est commité.
#
# Les huit valeurs légales, elles, sont nommées une seule fois dans ci/legal-placeholder.env, dont
# C18 vérifie qu'il porte exactement les noms d'AD-9. Les deux fichiers réunis nomment les **douze**
# secrets que la mise en ligne exige, et aucun script n'en recopie la liste (point 19 d'AGENTS.md).
#
# Lu par :
#   - scripts/release/ship.sh                  les entrées DEPLOY_*, qu'il exige dans l'environnement
#   - scripts/release/check-forge-secrets.sh   les quatre, confrontées aux secrets du dépôt
#   - scripts/tests/test-workflows.sh          pour tenir .gitea/workflows/release.yaml égal à ce fichier
#
# **Le workflow, lui, ne peut pas lire ce fichier.** Un YAML d'Actions ne lit aucun fichier du dépôt,
# et « ${{ secrets.NOM }} » s'écrit un nom à la fois : le mappage nominatif est d'ailleurs ce qui
# fait qu'un job ne reçoit que les secrets qu'on lui nomme. La copie dans le YAML est donc
# inévitable, et c'est un cas de test qui la tient égale à ce fichier — le même partage que pour les
# valeurs légales, dont le YAML recopie aussi les noms.
